# 审计报告要求

报告分两部分：**人读报告**和**机器结果**。人读报告是最终交付物；机器结果是附录，必须先通过 `audit-result.schema.json` 和 `evaluation_tool.py validate-result` 校验，再由 `report_renderer.py` 渲染成人读报告的附录部分。

## 人读报告（必需）

按以下结构写，全部用日常中文，不得使用自造术语：

1. **总结**：3-5 句话说清楚——审了什么、总体结论是什么、最重要的问题是什么。
2. **结论**：`PASS_WITHIN_FROZEN_SCOPE`、`NEEDS_REVISION`、`REJECT`、`INCOMPLETE` 或 `BLOCKED` 之一，附一句人话解释为什么是这个结论。
3. **逐条发现**：每条命中的规则写一段人话——问题是什么、出在哪里（用“文件:位置”形式）、为什么算问题、建议怎么改。未命中的必查红线用一小节概括说明查过且没发现问题。
4. **清单外的新问题**：审计中主动提出的新假设、观察到的迹象、是否被证伪、下一步怎么验证。
5. **未完成事项**：没查完的、缺证据的、被阻塞的，逐条列出原因。
6. **附录：机器数据**：校验和、分片编号、状态枚举、逐规则机器结果等，仅供工具核对，正文不得直接堆这些数据。

## 机器结果必需内容

1. 冻结目标路径及内容索引中的完整文件集校验和。
2. 审计模式、登记表校验和和选择校验和。
3. 选中规则与全部未选理由。
4. 每条已选规则的修订、严重度、状态、分片标识与分片校验和组成的证据引用，以及理由。
5. 清单外新假设、可观察信号、反证和下一探针。
6. 覆盖状态与必过检查失败项。
7. 可执行验收工件状态：`VERIFIED`、`ABSENT`、`NOT_APPLICABLE` 或 `UNCHECKED`。
8. 结论限制与未完成项。

## 判定用词

- `HIT`：有绑定证据证明问题存在。
- `NOT_HIT`：完成要求的证据检查后，确认问题不存在。
- `NOT_APPLICABLE`：适用条件不成立，并给出证据。
- `UNCHECKED`：所需证据缺失或还没查；不得改写为未命中。

任一 `critical` 或 `high` 规则为 `UNCHECKED` 时，结论只能是 `INCOMPLETE` 或 `BLOCKED`。

结果中的规则集合、修订和严重度必须与外部选择制品精确一致；目标文件集、索引、覆盖记录、覆盖清单、登记表和选择校验和必须回读并重算。不存在的证据字符串不能替代可解析分片。`FM-01 + FM-05`、`FM-05 + FM-06` 或可执行验收工件为 `ABSENT` 时，结论只能是 `REJECT` 或 `BLOCKED`。

## 结论含义

- `PASS_WITHIN_FROZEN_SCOPE`：冻结范围内全部必过检查通过；不代表普遍正确。
- `NEEDS_REVISION`：存在可修复缺陷。
- `REJECT`：红线组合命中或结构性缺陷，要求重写。
- `INCOMPLETE`：证据、覆盖或检查不完整。
- `BLOCKED`：缺少权限、独立性或外部状态，无法形成有效结论。

自审时 `status` 必须是 `SELF_AUDIT_SUBMITTED_FOR_EXTERNAL_REVIEW`，且结论不能作为接受依据。

## 复用时的报告边界

`REUSE_IDENTICAL` 表示本轮没有重新运行语义审计。调用方沿用回执绑定的旧机器结果和旧人读报告，不生成新报告，也不改写旧报告中的 `audit_id`、`self_audit`、`status` 或 `conclusion`。

交付说明必须列出被沿用的旧结果、复用判定收据摘要、原结论及其冻结范围。复用判定没有接受资格，不能把 `AUDIT_SUBMITTED_FOR_REVIEW` 升级为外部接受，也不能把自审改称独立审阅。
