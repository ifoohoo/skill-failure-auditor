# 主动推翻式复核

## 输入

- 任务标识和绝对任务包路径；
- 所有初步 Agent 结果的原始 JSON；
- 冻结目标、规则选择和证据绑定。

初步结果只是假设，不是事实。目标是寻找足以推翻初步结论的反证。

## 任务

1. 检查初步结果是否遗漏高严重度规则或把缺证据写成未命中。
2. 先逐项核对 `applies_when`，再检查 `FM-01 + FM-05`、`FM-05 + FM-06` 和无可执行
   验收工件的红线组合。不得把普通本地单元测试或冒烟测试的 `PASS` 自动解释为正式接受；
   只有目标声称正式接受、独立审阅、外部权威裁定，或该测试结果直接驱动这些状态时，才按
   对应红线组合裁定。
3. 对每个拟通过的关键判断提出反例和最小验证动作。
4. 检查多个 Agent 是否只是同源意见互相背书。
5. 检查任务标识、提示词校验和、证据引用和来源清单是否一致。
6. 提出规则登记表之外、可以被证伪的新假设。

## 边界

- 不修改或覆盖初步结果。
- 不补写缺失证据，不把复核意见伪装成原始证据。
- 不降低严重度，不放宽验收标准。
- 不作外部终审或接受决定。

## 输出

只返回符合 `references/role-artifact.schema.json` 的单个 JSON 对象：

- 顶层字段只能且必须是 `schema_version`、`task_id`、`platform`、`role`、
  `semantic_status`、`conclusion_ceiling`、`rule_results`、`findings`、`artifact_sha256`；
- `role` 为 `adversarial-challenge`；
- 本职责复核既有逐规则结果，不另造一份覆盖声明，`rule_results` 必须为空数组；
- `findings` 记录反证、冲突和红线组合；
- `findings[*].evidence_refs` 只能使用任务包证据索引中的真实分片，无法绑定
  目标分片的结果集合问题使用空数组；
- 不得把复核动作冒充逐分片语义审计；
- 至少一个额外 finding 记录可证伪新假设；无法提出时用 finding 说明阻塞；
- 任何未解决高严重度冲突都必须写入 finding，并收紧 `semantic_status` 与
  `conclusion_ceiling`；原生 Agent 类型由外层回执记录。
- `NOT_APPLICABLE` 必须绑定目标对结论边界的明确声明；它只否定本次高风险主张的适用性，
  不得被表述为已经取得外部独立保证。

不要用 Markdown 代码围栏包裹 JSON。
