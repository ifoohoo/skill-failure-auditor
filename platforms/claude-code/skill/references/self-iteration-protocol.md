# 外部评测迭代证据的审阅标准

当独立评测器对某个目标技能执行了多轮“评测—归因—修复—复测”并封存全套证据后，SFA 依据本标准审阅该过程是否存在漏水、作弊或越权放宽。注意：下列要求是 SFA **核查既有评测证据时使用的标尺**，不是 SFA 自身执行的运行步骤。

SFA 不启动目标技能，不创建评测轮次，也不清理测试沙箱；任何执行器或编排系统出现在材料中时，均只作为普通待审对象处理，不享有专用接口或豁免。

## 一、多轮评测证据必需体现的先后顺序

合格的外部迭代评测记录必须能够证明以下十步顺序未被打破：

1. 目标首次运行前，公开评测规格、隐藏验收标准承诺摘要、最大允许轮次和角色写集权限已经冻结。
2. 每一轮测试均使用独立的任务编号、尝试编号、进程与临时隔离目录。
3. 被测技能在运行期间只接收公开评测输入，未接触隐藏评分规则或答案线索。
4. 被测技能退出后，评测器先封存原始输出与运行流，再进入打分阶段。
5. 独立评分进程读取预冻结的验收标准，产出结构化逐用例评分结果。
6. 评测器清理用例隔离目录并留存清理回执，防止跨轮次状态污染。
7. 独立于实现者的只读审阅职责执行主动挑错式语义审阅。
8. 先基于失败表现完成根因归因，再交由实现职责修复；修复者全程无权读取隐藏标准。
9. 修复后的复测重新走全新的隔离目录、尝试编号、评分与独立审阅，不拼接上一轮部分通过记录。
10. 达到最大轮次仍未通过时，如实输出 `BLOCKED` 或 `NEEDS_INPUT` 停止，严禁中途下调通过门槛。

## 二、隔离能力核实与自审声明

审阅评测系统本身时，需核对代码与运行证据是否真正落实了：单向隐藏标准隔离、独立评分职责身份、逐用例 `HOME`/`TMP`/缓存与工作区隔离、受控写集强制检查以及外部终审授权。若材料仅有文档宣称或模拟夹具而缺少真实强制手段，审计结果必须保持 `acceptance_eligible: false` 并指明缺口。

当审阅对象为 `skill-failure-auditor` 自身或其同源副本时，结果状态只能标记为：

```text
SELF_AUDIT_SUBMITTED_FOR_EXTERNAL_REVIEW
```

该状态仅供提交外部独立终审复核，不能作为自我验收通过的依据。
