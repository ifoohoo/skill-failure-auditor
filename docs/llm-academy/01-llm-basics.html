地基 · 机制决定行为

LLM 到底是怎么工作的

不讲数学，只讲机制——因为后面所有的「毛病」都能从这几个机制里推出来。读完这页你会获得一种能力：看到模型犯错时，能说出「哦，这是 XX 机制的必然结果」，而不是「这 AI 真笨」。

1

它只做一件事：预测下一个词

剥掉所有产品包装，LLM 在推理时只做一件事：给定一串 Token，输出「下一个 Token 是什么」的概率分布，选一个，拼回去，再来一遍。你看到的对话、代码、报告，全是这个循环一个字一个字堆出来的。

知识点：下一词预测与自回归生成
🏠 生活类比
一位用不能回退的打字机写作的成语接龙大师。每敲一个字都成为既定事实，写错了不能撤销，只能顺着往下圆。所以你会看到模型「一本正经地把错误编圆」——它不是嘴硬，是机制上没有撤销键。
🎓 学术表达
自回归语言建模（Autoregressive Language Modeling）：对序列的联合概率按链式法则分解，模型学习条件分布 P(下一词 | 前文)。推理即从该分布逐步采样，已生成内容成为后续步骤条件的一部分。
🔧 工程表达
输出是逐 Token 流式产生且不可回滚的。含义：① 开头错则全程错，早期输出质量决定全局；② 让模型「先想后写」（先输出计划/推理再给结论）能显著改善多步任务；③ 「重新生成」比「让它自我修正」经常更有效——推倒重来没有历史包袱。
🧪 复现方式
让模型口算「17 × 24 - 138 ÷ 6」并要求「只给最终数字，不许写过程」，多试几次观察出错率；再允许它写步骤重试。前者逼它「一口报出答案」，后者允许它把中间结果写进上下文当草稿——正确率差异肉眼可见。
🛠 对策
  • 复杂任务要求先输出计划、分析或推理链，再给结论——把「草稿纸」显式给它。
  • 发现方向性错误，别在原会话里纠缠「你错了重想」，直接改提示词重新生成。
  • 把长任务拆成多次短生成，每段之间由你或框架校验，避免错误随长度复利。
2

它看世界的方式：Token 与注意力

模型不认识「字」和「词」，只认识 Token。所有输入拼成一串 Token 放进上下文窗口，生成每个新 Token 时，注意力机制给窗口里每个旧 Token 打「关注度分」。这两个机制解释了一大批怪毛病。

知识点：上下文窗口 = 有限且不均匀的工作记忆
🏠 生活类比
一张固定大小的办公桌。材料多了只能收走旧的（截断）或叠起来压成一页纸（压缩）；而且桌角堆的文件名义上「在桌上」，你办事时根本不会翻到它。
🎓 学术表达
上下文窗口受最大序列长度约束；注意力权重随内容增长被稀释，且对序列首尾存在位置偏好（首因与近因效应），中部信息的有效利用率显著下降，即「迷失在中间」现象。
🔧 工程表达
窗口是稀缺资源，要当预算管理：① 塞进窗口 ≠ 被利用，长度越长边际利用率越低；② 关键约束的位置是设计变量——开头定基调、结尾定行为；③ 「大窗口」是容量指标不是质量承诺，200K 窗口塞满后的表现要实测。
🧪 复现方式
经典「大海捞针」实验的日常版：把一条独特要求（如「输出中必须包含暗号 X-217」）分别埋在一份 50 页材料的开头、正中、结尾，各跑一次同样的任务，看哪次暗号丢了。中部丢失率明显更高。
🛠 对策
  • 关键红线在入口、执行前、最终检查三处重复（对应 FM-08 的解法）。
  • 长材料先做结构化摘要再喂，或用检索按需取片段，别整本倒进去。
  • 长会话定期「清桌子」：总结进展、开新会话、用交接包续接（详见 04 页）。
3

它的性格哪来的：训练三阶段

模型的能力和毛病都是训出来的。三个阶段各留下一笔遗产：

阶段做什么🏠 类比留下的正面遗产留下的毛病
预训练海量文本上学「接下一个词」原生家庭 + 义务教育语言能力、世界知识、代码模式幻觉的土壤、训练数据的偏见、知识截止
指令微调用「指令→理想回答」样本教它对话岗前培训：学会「别人提问要回答」听得懂指令、会按格式输出倾向「永远给出一个答案」，哪怕不该答
对齐训练按人类偏好打分强化服务业培训：「顾客永远是对的」礼貌、安全、有用性谄媚、过度道歉、回避明确立场
🔑 工程含义
「倾向于永远给出答案」+「倾向于让你满意」这两条训练遗产叠加，就是它宁可编也不说「我不知道」、宁可附和也不坚持事实的根源。所以「逼它承认不知道」永远不如「给它检索工具」和「用外部校验兜底」。
4

同一个问题两次答案不一样：采样与温度

知识点：输出是采样出来的，不是查表查出来的
🏠 生活类比
点菜的冒险程度旋钮：温度 0 是每次都点最稳的招牌菜（稳定但呆板），调高温度是让服务员随缘上菜——惊喜和翻车都变多。同一家店，两次上的菜可以不一样。
🎓 学术表达
解码策略：从模型输出的概率分布中采样。温度参数缩放分布形状——低温趋向贪心解码（近似确定），高温提高低概率词的采样机会，增加多样性同时提高偏离风险。
🔧 工程表达
非确定性是默认行为：① 「上次能跑通」不构成回归保证，关键链路每次都要验；② 需要可复现时降温度、固定随机种子（如果接口支持），但仍不承诺跨版本一致；③ 反过来可以利用它——同一任务采样多次投票（自洽性策略），用冗余买可靠性。
🧪 复现方式
同一个中等难度问题（如「给这段函数找 bug」）连问 5 次（每次新会话），对比答案。你会看到：结论方向可能一致，但覆盖点、遗漏点、置信语气各不相同——这就是为什么「跑一次就信」很危险。
🛠 对策
  • 关键判断多采样几次取交集/多数票，分歧点就是需要人工介入的点。
  • 流水线里的模型环节要按「非确定性组件」设计：下游必须有校验，不能假设幂等。
  • 创意任务调高随机性，事实与代码任务压低随机性——一个旋钮别忘了拧。
5

能力从哪冒出来的：涌现与不规则边界

模型规模跨过门槛后会「突然会了」一些能力（涌现能力），但这些能力不沿人类的难度直觉分布：会做奥数题的模型可能数不清单词里的字母。这条「锯齿状能力边界」直接决定了你该怎么授权：

⛔ 授权错误的典型剧本
「它连架构设计都聊得头头是道，改个配置文件肯定没问题」→ 配置文件语法冷门、训练语料少 → 改错 → 但它输出的置信语气和聊架构时一模一样 → 你没检查 → 事故。能力边界必须实测，不能用「难度感觉」外推。这也是 FM-19（做不了主的角色握着决定权）在人机协作里的映射：授权要按实测能力发放，不按谈吐印象发放。
💡 上岗前自检三问
① 这个任务里模型犯错，我能在多久内发现？② 发现时的代价是多少？③ 我有没有对这类任务做过至少 3 个样本的实测？——三问有一问答不上来，就先降级授权（只让它出草稿，不让它直接落地）。
🎫

出口 · 速记卡

一句话本章：LLM 是「用不能回退的打字机做成语接龙的失忆天才」——所有毛病都是这个设定的必然推论。

  • 三个必背：① 它优化「像不像」不优化「对不对」；② 窗口内的内容两头受宠、中间遭殃；③ 输出是采样的，跑一次不算数。
  • 一个数字：关键红线要在 3 个位置重复——入口、执行前、最终检查。
  • 开会行话：「这是机制性弱点，围堵而不是修复」「先实测能力边界再授权」。
