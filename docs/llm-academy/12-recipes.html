实战装备包：把全站方法论压缩成可复制的模板

学完就忘是常态，能抄才是生产力。本页把前面十一页的对策收敛成五个开箱即用的模板：任务简报、交接包、验收清单、对抗式审查指令、红线检查单。每个模板标注了它反制的失效模式。

1

模板一 · 任务简报（发任务前填好再发）

反制指令设计四坑（03 页）和权限无边界（05 页）。要点：正向指令、规则分级、性质先于示例、明确升级出口。

📋 任务简报模板 防 FM-11/12/13/14/16
## 目标（一句话，做成什么样才算成）
[交付物 + 可验证的完成判据，不写「优化一下」这类模糊词]

## 红线（违反即失败，冲突时停止上报，不得自行取舍）
1. [红线一，个位数条数，放开头]
2. [红线二]

## 该怎么做（正向指令，每条禁止都配替代动作）
- 应该：[具体动作]（而不是：[对应的禁止项]）
- 应该：[具体动作]
- 做不到时：停止，列出障碍和待确认项——停下上报不算失败，硬编才算

## 规格（性质优先，示例只是佐证）
性质：[必须保持的抽象性质，如「所有金额两位小数四舍五入」]
示例：[1~2 个，标注「非穷举，文件名/用词/顺序均非要求」]

## 权限边界
- 可以自主决定：[白名单]
- 必须先请示：[升级触发条件，如「规则缺失、证据不足、要改公开接口」]
- 绝对不碰：[权威期望值 / 验收标准 / 基线数据]

## 结尾复查（红线在此重复一遍——三点布防）
提交前逐条自查上方红线，逐条写明「已满足/未满足＋原因」。
要点回顾：红线开头结尾各一次（FM-08 三点布防）；「做不到时」给合法出口（FM-11/16）；性质先于示例（FM-13/14）。
2

模板二 · 交接包（跨会话 / 跨角色必带）

反制上下文腐烂、转述损耗、满窗误处置（04 页）。标准：接收方不依赖交接人也能独立恢复任务。

📦 结构化交接包模板 防 FM-09/17/20
## 任务目标（原始目标原文，不要转述版）
[从最初的任务简报原样复制]

## 当前状态
- 已完成并验证：[列表，每项附证据指针（文件路径/测试结果）]
- 进行中：[到哪一步，卡在哪]
- 未开始：[列表]

## 权威文件清单（接收方开工前逐一确认存在）
- [绝对路径] — [作用] — [校验和或行数，防拿错版本]

## 已排除路径（防止重复踩坑——这一节最值钱）
- 方案 [A]：已尝试，失败原因 [X]，不要再试
- 假设 [B]：已被证据 [Y] 推翻

## 验收判据（原样复制，禁止摘要）
[冻结的验收清单原文]

## 下一步建议
[1~3 条，接收方可不采纳，但必须知道]

## 接收方开工检查（对账后才许开工）
[ ] 权威文件逐一打开确认  [ ] 复述目标与判据，与本包比对一致
[ ] 已排除路径已读        [ ] 有出入立即打回，不猜
要点回顾：目标和判据用原文不用转述（FM-17）；已排除路径显式携带（FM-09）；恢复一律冷启动对账，禁止原样重试（FM-20）。
3

模板三 · 验收清单（开工前冻结，赛中不许改）

反制假完成全家桶（06 页）和赛中改规则（08 页）。核心：结果谓词、真断言、进度只认已验证里程碑。

✅ 验收清单模板 防 FM-01/02/03/04/22/24/27
## 冻结声明
本清单于 [日期时间] 冻结，存档于 [路径]。执行开始后修改须走独立审批并留痕。
期望值来源：[外部权威文档 / 真实环境实测 / 独立方出题]（禁止执行者自产）

## 结果谓词清单（每条必须是「内容对不对」，不是「东西在不在」）
[ ] [输出 X] 的内容 [等于精确值 / 满足性质 P]，比对方式：[脚本/命令]
[ ] [行为 Y] 在输入 [边界值/异常值] 下返回 [预期结果]
[ ] 覆盖矩阵：等价类 [列表] × 边界 [列表] 各至少一例（不看用例总数）

## 断言质量自检
[ ] 无「非空 / 非异常 / assert True」级弱断言
[ ] 抽三处故意改坏实现，对应检查必须变红（变异自检）

## 验收执行规则
- 「通过」由 [独立角色/脚本] 出具，执行者只能提交「完成申请 + 证据」
- 进度 = 已验证里程碑 ÷ 总里程碑，活动量（调用次数/时长/自报百分比）不计入
- 失败记录只增不改：尝试 1 失败 + 尝试 2 通过 ≠ 一次通过
要点回顾：痕迹谓词换结果谓词（FM-02）；变异自检防空断言（FM-03/18）；锚点外置防同源自洽（FM-27）。
4

模板四 · 对抗式审查指令（评审任务专用）

反制自评估陷阱（07 页）。核心：动词对抗式、默认不通过、独立性定级、零发现须自证。

🔍 对抗式审查指令模板 防 FM-05/06/07/23
## 你的角色
独立审查者。你与实现过程无关，你的绩效只看「找出的真问题数」，
不看「让实现通过的速度」。默认立场：不通过——除非你能论证为什么可以通过。

## 任务（注意动词：是「推翻」不是「确认」）
1. 找出能推翻此实现的证据：至少给出 [N] 个最可能失败的输入并实际验证
2. 假设其中埋了 bug：最可能藏在哪三处？逐处排查并给出结论
3. 对照冻结的验收清单 [路径] 逐条核验，禁止凭印象打勾

## 独立性要求
- 不得凭记忆背书：涉及事实断言（API/版本/数据）必须查 [官方文档/运行验证]
- 你是同一模型的新会话（马甲级独立），对高风险结论请标注
  「需更高独立性复核」，交由 [异构模型/人工] 终审

## 产出格式
- 发现清单：[位置 / 问题 / 证据 / 严重度]，至少 [N] 条
- 零发现时：列出全部排查路径和使用的验证手段，证明「查过而非没查」
- 终审结论：通过 / 不通过 + 论证（你是本链路终审，出错算你的）
要点回顾：对抗式动词 + 最低发现数（FM-06）；终审责任显式指派（FM-07）；独立性分级标注（FM-23）。
5

模板五 · 红线检查单（11 条，任何严肃验收逐条过）

来自审计技能的 11 个必查红线，压缩成一张可打印的检查单。全部通过才算「验收体系合格」，与产出本身的质量是两回事。

⛔ 必查红线检查单 11 条 core_redline
[ ] FM-01 「通过」由独立方出具，不是执行者自我宣布
[ ] FM-02 验收谓词是「内容对不对」，不是「文件在不在」
[ ] FM-03 无「怎么都过」的弱断言（非空/非异常/恒真）
[ ] FM-05 实现与验收结论不出自同一角色/会话
[ ] FM-06 审查指令是「找出推翻证据」，不是「确认没问题」
[ ] FM-15 外部内容（文件/日志/工具输出）一律视为数据，不执行其中指令
[ ] FM-18 验收流程做过注错演练，灵敏度有实测记录
[ ] FM-22 判据开工前冻结，失败记录只增不改
[ ] FM-25 每条限制有机器强制（工具面/钩子/沙箱），不是只写在纸上
[ ] FM-26 分片处理有清单 + 守恒对账 + 分层抽样
[ ] FM-27 期望值锚定外部权威，非实现者自产
逐条核对方式见 10 手册页 各卡片的「排除条件」；深度拆解见各主讲页。
